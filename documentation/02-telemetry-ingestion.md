# Wazuh Telemetry Ingestion

## Overview

After configuring the Wazuh Agent on the Windows endpoint, telemetry was verified in the Wazuh Dashboard.

The purpose of this stage was to confirm that Windows Security events and Sysmon events were successfully being collected and forwarded to the Wazuh server.

![ActiveAgent](<screenshots/VirtualBox windows agent active.png>)

---

## Windows Security Telemetry

Windows Security event logging was verified through both Windows Event Viewer and Wazuh.

The following authentication events were observed:

| Event ID | Description |
|---|---|
| 4624 | Successful logon |
| 4625 | Failed logon |
| 4616 | System time change |

### Event ID 4624 — Successful Logon

Event ID 4624 was generated by performing a successful login to the Windows endpoint.

The event was subsequently identified in Wazuh, demonstrating that Windows Security authentication telemetry was being collected from the endpoint.

### Event ID 4625 — Failed Logon

Event ID 4625 was generated during controlled failed authentication attempts.

These events were subsequently identified in Wazuh and were later used as part of the brute-force investigation.

---

## Sysmon Telemetry

Sysmon was installed on the Windows endpoint to provide additional visibility into process and file activity.

The following Sysmon events were observed in Wazuh:

| Sysmon Event ID | Description |
|---|---|
| 1 | Process Creation |
| 11 | File Creation |

### Event ID 1 — Process Creation

Sysmon Event ID 1 was observed in Wazuh and provided information including:

- Process image
- Command line
- Parent process
- User
- Process ID
- Event timestamp

This telemetry was later used for the process creation investigation.

### Event ID 11 — File Creation

Sysmon Event ID 11 was observed in Wazuh and provided information including:

- Target filename
- Process image
- User
- Process GUID
- Event timestamp

This telemetry was later used for the file creation investigation.

---

## Telemetry Verification

Telemetry was verified by comparing activity observed on the Windows endpoint with events displayed in Wazuh.

Windows Event Viewer was used to confirm that events were generated locally, while Wazuh was used to confirm that the events were successfully collected and centralized.

This confirmed that the Windows endpoint was successfully communicating with the Wazuh server.

---

## SOC Value

Centralizing Windows Security and Sysmon telemetry in Wazuh provides a SOC analyst with visibility into:

- Authentication activity
- Process execution
- File creation
- User activity
- Endpoint events

This visibility can be used to identify suspicious behavior, correlate related events, and investigate potential security incidents.

---

## Conclusion

The telemetry ingestion stage successfully demonstrated that the Windows endpoint was communicating with Wazuh and providing both Windows Security and Sysmon telemetry.

The collected events provided the foundation for the authentication, file creation, and process creation investigations performed later in the project.
